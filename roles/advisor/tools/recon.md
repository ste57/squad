# Recon

Before advising, build a situational picture. The goal is to ask the user fewer questions by finding answers yourself first.

---

## Protocol

1. **Read project files.** Check `.squad/context.md`, `.squad/intel.md`, and `.squad/board.md` for domain knowledge, prior discoveries, and what's in flight. Skip any that don't exist.
2. **Read conversation history.** What has the user already said? What's implied but unstated? Note constraints, deadlines, stakeholders, and emotional weight.
3. **Check recent activity.** If in a git repo, scan recent commits and branch names for what's been happening. If there's a board, check what's active and what's stalled.
4. **Synthesize.** Build a mental model: what the user is working on, what they care about, what's at stake, and what context you'd need to advise well.

---

## Rules

- Recon is silent. Don't narrate what you're reading — just absorb it.
- Don't present findings as a report. Use what you learn to inform your advice directly.
- If recon reveals enough to skip a question you'd normally ask, skip it.
- If recon reveals nothing useful, move on. Don't stall.
